# 改善ノート：会話が変わっても、同じ根拠で答える

2026年11月 · 私用ツールの運用改善

## 01 起きたこと

就活管理の仕組みを使う中で、すでに完了した適性検査が、別のAI会話では未完了として扱われ、もう一度対応を求められることがありました。

## 02 原因の見立て

会話ごとに参照していた履歴が異なり、回答前に共通の記録を確認する手順が必要だと考えました。

| 確認すること | 改善前 | 改善後 |
|---|---|---|
| 状態の根拠 | 会話ごとの履歴に依存 | 共通の台帳を参照 |
| 回答前の確認 | 共通の確認手順が不十分 | 記録の内容と読んだ時点を確認 |
| 引き継ぎ | 結果の共有が中心 | 根拠・未確認事項・次の確認も共有 |

## 03 決めたこと

### 2つのAIの担当を分ける

Claudeは書類作成と資料整理を担当し、新しい材料、情報源、まだ確認できていない点をまとめて引き継ぎます。GPT / Codexは材料と対象の会社・募集を別途確認し、メールとの照合、台帳への登録、登録後の確認を担当します。Claudeは台帳を直接更新せず、状態の正本を1つに保ちます。書類の新版は別ファイルで残し、相手の原稿を上書きしません。

### 引き継ぐ内容と、確認が済んだ内容を分ける

引き継ぎには、識別ID、対象の会社・募集、材料の保存先、情報源、未確認事項、担当者と次の確認事項を残します。GPTは実ファイルを読み、同じものを二重に登録していないか、内容が途中で変わっていないかを照合します。対象が特定できないもの、根拠がまだ確認できないものは、確認待ちとして残します。

資料を受け取ったことと、企業へ提出したことは別に扱います。草稿が届いたことだけで応募済みにはしません。本人の確認や企業の受付通知など、該当する作業の根拠を確かめて記録します。提出済みを選考通過や別テストの完了には広げません。

### 回答する前に、同じ記録を読む

1. 作業開始時に、台帳の事実・情報源・未確認の報告・不足情報を読む。
2. どの会話が、どの範囲の記録を、いつ読んだかを残す。
3. 状態の回答や催促の前に、情報が更新されていないか、時間が経ちすぎていないか、対象が一致しているかを確認する。
4. 変更や時間経過があれば読み直す。読めないときは、確認できていないことを伝え、古い要約だけで未完了と判断しない。

本人から完了・提出・予約などの確認を受けた場合は、原文と確認日を保存し、根拠つきで台帳へ登録した後、別の接続でもう一度読み、登録結果を確かめます。確認した日と実際に行った日時も区別します。

### 不足や食い違いを、次の確認事項として残す

材料の欠落、内容の不一致、未受信の引き継ぎ、事実の衝突、完了後も残る古い対応事項を点検します。見つかった問題には担当者と次の確認事項を残します。
