# Shukatsu OS：根拠と文書の版から、今必要な一歩を選ぶ

[公開デモ](https://yaenyanyako.github.io/shukatsu-os-showcase/#guide) · [6分の操作ガイド](demo-guide.md) · [今回の更新](../CHANGELOG.md)

**4社・7プロジェクト・通知12件を、すべて新しく作った架空例で体験するワークフローデモです。** 実際の応募者、選考中の企業、応募書類、メール、日程、結果や私用台帳の件数は公開しません。

**私の役割：** 要件定義、情報設計、受け入れ確認、改善の優先順位付けを担当しました。会社と募集を分ける構造、根拠から状態を更新する条件、確認した文書を優先するルールを決めています。実装はAIコーディングツールの支援で行っています。

## 解決したかった問題

資料を保存しただけでは、次の判断が楽になるとは限りません。同じ会社の別募集が混ざる、説明会メモも応募書類も同じ分類になる、新しい草稿を確認済みの回答と取り違える、応募受付を面接への進行と誤解する、といった問題が起きます。

知りたかったのは「この募集はどの段階か」「使う文書はどれか」「必要な次の一歩は何か」「根拠は何か」です。会社 → プロジェクト → 出来事を軸に、通知、研究、文書、予定と行動をつなげました。

## 設計と動作

| 判断 | デモで確かめること |
|---|---|
| 同じ会社の募集を分離する | Asterの本選考とインターンでメール、期限、草稿と回答が混ざらない |
| 用途で資料を探す | 説明会と経験談は企業研究、本人の回答・履歴書はES、受領は応募記録へ。内部JSONは資料一覧に出さない |
| 確認版を優先する | 同じ設問の保存版を一組にし、本人確認v2を先に表示。後日の未確認v3は他の版に残り、日付と状態を読める |
| 確認と提出を分ける | 「本人確認版にする」は内容への確認。受領通知がない提出を完了にしない |
| 準備の時機を決める | 面談の明示的な案内、または書類通過通知がある募集で練習を開く。説明会や検査案内は面接進行にしない |
| AI面接案内を正しく扱う | 書類選考の一部という架空通知では、練習を開いても「書類選考中」のまま |
| 一歩だけを完了にする | インターンの回答フォーム受領を反映しても、同じ募集の適性テストは未完了。再反映で増えない |
| 未完了を省略しない | 保存中の招待、古い項目、期限未確認、未来の準備を含めて確認。返答なしでは状態を変えない |
| 日誌を推測しない | 本人が入力した非空の返答だけを保存。受領通知から活動日誌を作らない |
| 通知を再処理しても仕事を増やさない | 同じIDはスキップ。改期は同じ予定を更新して重複を再計算 |

ES編集では設問ごとに草稿と保存版を管理します。本人確認版がなければ最新保存稿を使います。古い保存状態も復元でき、記録されていない保存日時や確認を作りません。面接パックも同じ確認版を参照します。

企業研究は7観点と業界比較で整理し、架空の出所・年度・募集・段階を残して経験談を素材棚へ保存します。他者の経験談を、本人の実績や現在の選考ルールに変えません。

## 実際に動く操作と、架空例の境界

編集、版保存・確認、用途別表示、過去版の表示、状態ルール、回答保存、未完了の更新、日誌保存、PDFとICSの生成は、このブラウザで実行されます。入力はこのデモのローカル保存領域にとどまり、静的公開ファイルには入りません。

通知本文と抽出結果、企業情報、経験談、質問は手作業で作った架空例です。研究の「収集」は既知の架空資料IDを保存する模擬操作で、検索やスクレイピングをしません。ESと面接の助言は簡易ルールと固定文です。Calendarの「接続」は模擬同期で、GoogleやOutlookにログインしません。実メール、採用サイト、AI API、外部カレンダー、応募・予約・送信、夜間の自動実行は接続していません。

私用の作業環境ではローカル台帳と補助ツールを組み合わせますが、そのデータ、現在の選考企業、書類や実運用の件数は同梱しません。公開デモは情報設計と状態変化を架空例で説明するためのものです。

## 検証と次の評価

v2.1は45の自動テストで、通知ルール、募集分離、確認版の優先、旧状態の復元、面接の時機、受領の一歩限定、再処理、全未完了、本人返答とPDF/ICS構造を検証しました。公開ファイル38件の静的チェックも実行します。詳細は[検証範囲](evaluation.md)に記載します。

これらは実ブラウザの見た目・アクセシビリティ、AI精度、時間削減や採用成果の検証ではありません。次の評価では、根拠確認や版選択に要する時間、誤った状態への変更、確認版の取り違えを、条件を固定して測る必要があります。効果が未測定の段階で成果の数字を作りません。
