# 企業の要約から、選考ごとの確認へ

2026-11-10

同じ企業で複数の選考が進むと、別の面接の準備で「次の一手」が更新され、未確認の MyPage 通知が日次リストから見えなくなることがありました。通知そのものを保存するだけでは、必要な確認を継続できません。

## 変更した設計

- 企業・応募先に加え、選考ごとの ID を持つ。特定できない通知は未確認として残す。
- 通知を会社の要約やユーザーのタスクとは独立して追跡する。「既読」「処理済み」のフラグだけでは閉じない。
- 予約証拠は同じ選考にだけ適用する。予約確認とカレンダー照合を別々の義務として扱う。
- カレンダーは選考、予定 ID、最新の開始・終了時刻を照合する。改期前の予定では解決しない。
- 解決証拠を通知の出典に結び付けて保存する。後続の通知や再取り込みで過去の解決を失わない。
- 未特定の通知を後から選考に関連付ける場合は、変更前後と根拠を残す。

本人の未対応と、システムが未確認であることを区別しました。後者はアシスタント側の確認リストに表示します。

## 検証

非公開のローカル実装では、別選考の予約、要約の更新、改期、通知の再取り込み、古い通知の解決保持、通知の後日照合を回帰テストで検証しました。今回の公開更新は説明文のみです。運用中の Python 実装と個人データは非公開のままです。

## 私の担当と開発方法

実際の利用で起きた見落としから問題を定義し、通知の終了条件・誤通知を避ける条件・受け入れシナリオを整理しました。コードの実装、テスト追加、レビューには AI 開発ツールを使用しています。

## 範囲

既存の定時チェックで利用します。リアルタイム監視や、未接続の MyPage の自動取得は追加していません。この説明には個人の応募状況、メール本文、アカウント情報を含みません。
